# Larkdoc-sync · 飞书文档同步助手

[English](./README.md) · 简体中文

在 Obsidian 里写笔记，让同事在飞书文档里阅读和评论。Larkdoc-sync 通过本机的 [`lark-cli`](https://github.com/larksuite/cli) 发布笔记：第一次同步创建并绑定文档，后续更新同一篇，不用反复发新链接。

> **同步方向：Obsidian → 飞书 / Lark。** 飞书上的正文改动不会回写 Obsidian。需要保留的改动，请先合并到本地笔记，再同步。

## 版本亮点

- **新增本地发布日志。** 在 Obsidian 内查看笔记和文件的发布、同步及覆盖结果，失败时可直接查看错误详情。
- **改版管理窗口和操作入口。** 笔记右上角的 Lark 图标集中提供同步和链接操作；左侧栏打开新版「飞书文档同步助手」，用「已发布文件」和「发布日志」两个标签页分别管理绑定和查看记录。设置按基础、文档、同步和高级分组，常用选项更好找。

## 五分钟上手

需要桌面版 Obsidian **1.13.0 或更新版本**、飞书或 Lark 账号，以及 Node.js 和 npm（用于构建插件和安装 CLI）。

1. **安装插件。** 在源码目录执行 `npm ci` 和 `npm run build`。将 `main.js`、`manifest.json`、`styles.css` 复制到 `<知识库>/.obsidian/plugins/larkdoc-sync/`，然后重启 Obsidian，在「第三方插件」里启用 **larkdoc-sync**。也可以使用仓库里的 [`install.sh`](./install.sh) 将构建产物复制到知识库。
2. **连接飞书。** 打开插件的「基础配置」，安装或检测 `lark-cli`。如果还没有配置 CLI 应用，选择飞书或 Lark，按提示创建应用，再点「登录 / 重新授权」。如果检测不到已安装的 CLI，可以手动填可执行文件的绝对路径。
3. **选发布位置。** 想发到团队知识库，在「默认上传位置」填你有权限访问的 Wiki 页面链接，也可以填 Wiki 节点 token 或文件夹 token。不填时，笔记发到个人文档库。修改默认位置不会移动已绑定的文档。
4. **发第一篇笔记。** 打开 Markdown 笔记，点击标签页右上角的 Lark 图标，选择「同步到飞书」。已有飞书文档时，可先用「设置飞书链接」建立绑定，再同步。

## 日常使用

- **当前笔记：** 右上角的 Lark 菜单提供同步、覆盖同步、设置链接和打开链接。平时用普通同步；覆盖同步会按本地内容重写远端，也可能清理目标位置下的其他同名文件，执行前先核对目标。
- **目录和附件：** 在文件列表右键同步目录或独立 PDF。目录同步会保留层级，并在飞书端把已发布的笔记链接串起来。在 Obsidian 中同步笔记时，正文引用的本地文件（如 PDF、ZIP、TXT）可上传为文末可下载的原生附件卡片，不必先单独上传。支持 Obsidian 双链和标准 Markdown 链接；图片、视频嵌入和 PDF 指定页预览仍走原来的流程。Git `pre-push` 不负责上传这些附件；只修改附件时，请手动同步笔记。
- **自动同步：** 在「同步配置」选择「保存后同步」（默认）、关闭自动同步，或使用 Git `pre-push` hook。默认保存延迟是 15 秒；保存模式需要 Obsidian 正在运行。自动同步只更新已绑定的笔记，不会替你发布新笔记。若要把 PDF 作为独立云端文件发布，仍须手动同步或随目录上传；正文引用的附件卡片不需要这一步。
- **管理和排查：** 点击左侧栏 Lark 图标打开「飞书文档同步助手」。「已发布文件」用于查找链接和管理绑定；「发布日志」显示近期的发布、同步和覆盖结果。有错误先看日志里的文件路径和提示。日志只写入本地 `publish-log.json`，保留最近 500 条，不计入无变化的跳过和 Git hook 同步。

## 同步之前，先确认这几件事

| 场景 | 怎么做 |
| --- | --- |
| 想把 PDF 作为附件下载 | 在笔记内使用普通 PDF 链接。`![[文件.pdf#page=2]]` 仍用于指定页预览，不等同于原生附件卡片。 |
| 不想把草稿发出去 | 右键目录，选择「选择忽略的文件」。规则保存在 `.feishuignore`，会作用于目录同步、保存后同步和 Git hook；手动同步单篇时不受该规则限制。 |
| 想保留飞书的块评论或定位链接 | 优先普通同步。默认策略在无法增量更新时可能重写正文；不能接受重写时，选择「安全增量同步」。已有文档首次转换为原生 Callout 也会重建正文。 |
| 自动同步没反应 | 确认笔记已有绑定、「保存后同步」已启用、Obsidian 仍在运行，并检查忽略规则。 |
| 文档发错位置 | 先检查这篇笔记的绑定。默认上传位置只管新发布，不会改变现有链接。 |
| `git push` 被同步失败阻断 | 解决 hook 报出的错误，或把「自动同步方式」切换到其他选项。Git hook 和网络代理都在默认折叠的「高级配置」里。 |

「文档配置」用于调整标题来源、是否同步后打开文档，以及是否把 `lark_doc_url` 写进笔记的 frontmatter。插件默认只把绑定保存在本地插件数据里。更多 Callout、PDF 页码和选区导出细节见[原生导出说明](./docs/native-export.md)。

## 网络与隐私

插件通过本机 `lark-cli` 调用飞书或 Lark 的官方 API。发布或同步时，选中的内容和相关附件会发到授权账号的目标位置；安装或更新 CLI 时，npm 会连接软件包仓库。登录凭据保存在 CLI 的本地认证存储中，不写入笔记、插件设置或发布日志。插件没有独立的遥测上报。

## 开发与许可

开发时用 `npm run build` 生成插件，用 `npm test` 运行测试，用 `npm run release:check` 校验版本与发布说明。历史见[变更日志](./CHANGELOG.md)，发布说明见 [`release-notes/`](./release-notes/)。
